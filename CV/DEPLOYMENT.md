# Protected CV Deployment

## What gets deployed

Build the Jekyll site and deploy the generated output as a PHP site on alwaysdata.

The important protected files are:

- `CV/index.php`
- `CV/login.php`
- `CV/logout.php`
- `CV/asset.php`
- `CV/login.css`
- `CV/.htaccess`
- `CV/auth/password.local.php`
- `CV/content/index.html` generated by Jekyll from `CV/cv.markdown`
- `CV/assets/pdf/szilvia-varga-cv.pdf` generated from `CV/download/cv-download.md`
- `CV/assets/...` for CV-only CSS, JS, and images

## Local password setup

1. Copy `CV/auth/password.local.php.example` to `CV/auth/password.local.php`
2. Generate a password hash:

```bash
php -r "echo password_hash('your-new-password', PASSWORD_DEFAULT), PHP_EOL;"
```

3. Paste the hash into `CV/auth/password.local.php`

## Build

Install the PDF build dependencies once:

```bash
npm install
```

Update the downloadable PDF from `CV/download/cv-download.md`:

```bash
npm run build:cv-pdf
```

Or build the PDF and the release site together:

```bash
npm run build:site
```

If you still prefer the original Jekyll command, run the PDF build first:

```bash
npm run build:cv-pdf
bundle exec jekyll build --destination _site_release
```

On Windows, this avoids overwrite issues with hidden `.htaccess` files in an older build folder.

After the build, verify these files exist in `_site_release`:

- `_site_release/CV/index.php`
- `_site_release/CV/login.php`
- `_site_release/CV/logout.php`
- `_site_release/CV/asset.php`
- `_site_release/CV/login.css`
- `_site_release/CV/.htaccess`
- `_site_release/CV/auth/password.local.php`
- `_site_release/CV/content/index.html`
- `_site_release/CV/assets/pdf/szilvia-varga-cv.pdf`
- `_site_release/CV/assets/...`

## alwaysdata

1. Create one site on alwaysdata with type `PHP`
2. Set its document root to the folder where you will upload the built files
3. Upload the contents of `_site_release/` into that document root
4. Make sure `CV/auth/password.local.php` is uploaded too
5. Visit `/CV/login/` and test the password
6. Visit `/CV/` and confirm it redirects to `/CV/login/` when logged out

You are uploading the built files, not the source Jekyll project.

Result:

- the main portfolio remains public
- `/CV/` is protected by the PHP session gate
- `/CV/login/` is the password page
- `/CV/assets/...` is served through PHP only after login

## Rotating the password

1. Generate a new hash
2. Replace the hash in `CV/auth/password.local.php`
3. Rebuild the site
4. Upload the updated `_site_release/CV/auth/password.local.php`
